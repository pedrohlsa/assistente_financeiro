## Como trabalhar aqui

- Sonde em conversa de vários turnos, como a tela, passando `pending`, `pendingClarification`, `draft` e `focus`. Use o fixture rico (`motoristaRico`) e também um estado vazio.
- Todo conserto começa com um caso que falha no código antigo. Confira com `git stash push -- src`, rodando só o bloco novo.
- Depois de cada lote, rode:
  - `npm test`;
  - `node node_modules/typescript/bin/tsc --noEmit`;
  - `npm run typecheck:api`;
  - `npm run rubric`, que precisa de 0 respostas PERIGOSA;
  - `npm run test:calendario`.
- **Não rode sondas enquanto a matriz roda.** A carga da máquina já reprovou o fuzz por tempo (327 ms contra o teto de 246 ms), e a repetição limpa passou com 106 ms.
- `--probe` do adversarial usa a data REAL. O fixture pode não ter movimento hoje, então o oráculo precisa tolerar isso.
- Leitores que rodam ANTES das cláusulas podem capturar a frase primeiro:
  - o dia telegráfico (`parseDriverDay`);
  - `platformPayout.ts`;
  - `spokenTotals.ts`;
  - `acrescimoAProposta` (o acréscimo "e N de X" com proposta na tela).
- Regras transversais desta rodada:
  - `semSomaDasPartes` (orquestrador): total dito com as partes não conta em dobro.
  - `totalComDoisPontos`, `abastecimentosRepetidos`, `valorPorCorrida` e `marcoDaRevisao` (nlp, aplicadas em `analyzeMessage`).
  - Rotas novas do motorista em `driverInsights.ts`: preço do litro, prejuízo de rodar, hodômetro, dias rodados e folgas, alvo dito contra o ritmo medido, horário.
